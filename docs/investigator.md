# Historical evidence investigator

`POST /v1/investigate` (also `/v1/assistant`) performs read-only, bounded natural-language research. The FastAPI application must mount `backend.assistant.router` under its authenticated `/v1` router. It neither saves reports nor changes agent behavior.

```json
{
  "question": "Did repeated review requests precede the handoff?",
  "history": [{"role": "user", "content": "By review I mean human review."}],
  "context": {
    "filters": {"source": "ai-village", "agent_id": "agent-uuid", "from_time": "2026-01-01T00:00:00Z"},
    "corrections": ["Review means human review, not automated checks."],
    "source_ids": ["events:source-uuid"]
  }
}
```

The reusable async function is `investigate(question, history, context, retrieval, provider=...)`. `retrieval` implements sync or async `search(q, **filters, limit, cursor)`, `graph(seed, hops, limit)`, and `record(table, source_id)`, using the Store envelopes. AI Village also exposes `context(seed, before, after)` for nearby chronological evidence. `provider.complete(system, payload, max_tokens)` returns a JSON object. Tests inject both interfaces without network access.

For “what happened next,” the investigator fetches up to three preceding and four following records around the first resolved focused source ID (or first search result). Temporal records are prioritized within the evidence budget. The returned `temporal_context` explains the scope and ordering: same session, SDK session, room, or table/agent fallback. Ordering may use a recorded event index instead of a timestamp. Nearby records establish sequence within that scope, not a causal response, successful execution, or completed outcome. Swarm Traces has no such temporal-context API; its graph describes recovery ancestry instead.

Both planning and synthesis use JSON mode with prompt constraints and the server validator. Explicit provider response schemas returned HTTP 400/timeouts during compatibility tests and are deliberately not sent. Synthesis includes an explicit retained-ID whitelist. Findings allow at most six source IDs and six exact quotations. Provenance-only IDs are not citation candidates. Server-computed identical-excerpt groups provide counts for the retrieved sample; this does not establish full-record identity when excerpts are truncated or corpus-wide repetition rates. All providers pass the same server validator. Prompt bytes count toward the input budget.

The response includes `status`, `answer`, `findings`, `unknowns`, `suggested_followups`, `proposed_tests`, `sources`, `query_plan`, `coverage`, `context`, and `model`. Status is `ok`, `insufficient_evidence`, or `model_unavailable`. Clients must distinguish these states; a provider failure is never represented as a simulated AI response. `sources` include stable canonical `table:source_id` IDs, excerpts and provenance. Findings contain exact quotes and source IDs; the server removes a finding if any citation is absent from retrieved evidence or lacks a matching quotation. `answer` is assembled only from the citation-checked findings. This validates citation existence and quote matching, **not semantic entailment or causal truth**; readers should inspect the linked evidence. The machine-readable report label is `epistemic_status: ai_draft_semantic_support_unverified`, and findings carry `validation: quote_matched_semantic_support_unverified`. A conservative lexical guard also rejects explicit causal or quantified intervention-effect assertions. Explicit uncertainty or negation within the same clause (for example, “cannot establish that an internal loop caused the repeated text”) is retained; negation in an earlier clause does not exempt a later causal assertion. This is not a complete semantic verifier. `coverage.rejection_reason_counts` distinguishes invalid structure, text limits, unknown IDs, invalid evidence types, missing quotes, quote length limits, exact-quote mismatches, and asserted causal effects, without exposing rejected model content. Exact quotation matching is unchanged. `excluded_source_reason_counts` separately reports scope exclusions and record/input-budget clipping; source-ID rejection diagnostics distinguish unknown IDs, known-but-excluded IDs, and excess citations. Focused source IDs take priority over peripheral records when clipping model context.

The caller passes conversation state each turn. Only the latest 12 messages (1,500 characters each), latest 6 explicit corrections (1,500 characters each), and current scope filters reach the model. Preserve returned `context.corrections` across turns, adding explicit user corrections as they occur. Truncation is reported. Earlier assistant statements are context, never evidence. Filters apply to search, pinned records, and graph-expanded records. Scope supports `source` (`ai-village` default or `swarmtraces`), `agent_id`, `table`, `from_time`, `to_time`. The endpoint routes the selected source through the application's `source_store`; it never silently falls back to AI Village. Swarm Traces rejects identity/time filters because it does not establish reliable actor identities or event timestamps. Upstream table ingestion coverage, source limitations, search-snippet metadata, and excerpt truncation flags are preserved in the model context and response.

Readable actor names come only from recorded agent rows or the Store's exact-ID joins, with `actor_name_provenance` preserved. Names are not inferred from mentions. An agent association does not establish authorship of SDK user/tool/system messages. The model is instructed to use recorded names in prose and canonical IDs in citations.

Follow-up generation receives an explicit list of available corpus retrieval tools. `suggested_followups` remains a string list for UI compatibility; questions needing unavailable evidence receive the prefix `External evidence required:`. The parallel `followup_scopes` list exposes `{question, scope}` with `available_corpus` or `external_evidence_required`. A conservative check also labels repository, system-prompt, external-log, and live-test requests as external rather than implying access. It may overlabel questions about such content that was already captured; clients can still search the historical corpus explicitly.

## Provider configuration

Install `httpx`, `google-auth`, and `requests` with the backend dependencies. Vertex is the default, using Application Default Credentials, including the VM service account; no credential file or API key is required on a properly configured VM.

```sh
INVESTIGATOR_PROVIDER=vertex
GOOGLE_CLOUD_PROJECT=your-project
GOOGLE_CLOUD_LOCATION=global
VERTEX_MODEL=gemini-3.5-flash
OBSERVATORY_DB=/path/to/observatory.sqlite
```

Enable the Vertex AI API and grant the service account the appropriate Vertex AI inference permission (normally `roles/aiplatform.user`). ADC obtains short-lived credentials at request time; credentials and provider error bodies are never returned to clients. The official [Vertex quickstart](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/start/quickstart) documents ADC and `generateContent`. On October 4, 2026, the official [model lifecycle page](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-versions) lists `gemini-2.5-flash` retirement as **October 20, 2026**. The deployment team verified `gemini-3.5-flash` with the VM service account, so it is now the default. `VERTEX_MODEL` remains configurable. Gemini 3 uses `thinkingLevel: MINIMAL` so planning can return JSON within its 600-token cap; the model default consumed that budget in the first live smoke. Sampling overrides are omitted, following the official [Gemini 3.5 Flash guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-5-flash). Gemini 2.5 Flash overrides use `thinkingBudget: 0` instead.

An explicit optional OpenAI-compatible configuration uses `INVESTIGATOR_PROVIDER=openai`, `OPENAI_API_KEY`, `OPENAI_MODEL`, and optional `OPENAI_BASE_URL` (default `https://api.openai.com/v1`). It uses HTTPS Chat Completions JSON mode with `max_completion_tokens`, as described in the official [structured-output documentation](https://developers.openai.com/api/docs/guides/structured-outputs). Other providers must support that schema. There is no automatic credential search or silent provider fallback.

## Bounds and interpretation

Each investigation normally makes two model calls and permits one additional bounded quote-format repair only when all findings fail quotation validation, three keyword searches, eight retrieval calls total (including temporal context), one graph expansion (one hop, twelve nodes), and retains at most 24 source records with 1,600-character excerpts. The synthesis input has a 48,000-byte bound, a conservative upper bound on text token volume. Output is capped at 3,200 tokens, 128 KiB wire response, eight findings, six citations per finding, and six items in each follow-up list. Planning is capped at 600 tokens. Optional repair is capped at 2,400 output tokens and 30 seconds, starts only within the first 100 seconds, and runs at most once. The investigator has a shared 135-second deadline; every model and retrieval call is bounded by its remaining time, and the endpoint has a 140-second ceiling. Regular provider calls have 60-second ceilings and retrieval calls 15 seconds. Four concurrent HTTP investigations are admitted per process; additional requests receive 429 after a one-second wait. Apply deployment-level authentication, request body limits, and per-user rate limits in front of this service.

The model has no SQL, shell, mutation, network, or action tools. Record text and graph contents are explicitly untrusted evidence. Model-produced queries can only enter the Store search interface; they cannot become executable SQL. Graph node IDs are resolved through the Store record API before citation. Search results are a bounded sample, never a whole-corpus count or an exhaustive absence claim. Generated summaries are marked secondary evidence. Historical associations do not establish causal root causes or intervention effects. Proposed tests carry `status: proposed_not_executed`.

Run deterministic checks with `python -m unittest backend.test_assistant -v`. Twenty-four tests exercise citation rejection, quote matching, malicious trace strings, correction context and clipping, chronological context, graph expansion budgets, source and time scope enforcement, recorded actor names, external-evidence follow-up labels, corrected repetition claims, negated causal limitations, rejection diagnostics, empty evidence, and honest model outages.

Authenticated deployment checks on October 4, 2026 used the VM service account and `gemini-3.5-flash`. The AI Village investigation completed in 12.95 seconds with three findings, twelve retrieved records, eight retrieval calls, and same-room chronological context. The Swarm Traces investigation completed in 14.62 seconds with two findings, four records, and eight retrieval calls; every source belonged to Swarm Traces. In both checks, every returned quotation matched both the response excerpt and a fresh authenticated record-API lookup. Missing outcomes remained explicit, and no proposed intervention was reported as performed. These are integration smoke checks, not a general semantic-accuracy evaluation. The initial planning-token failure was corrected with the thinking configuration described above.

The initial synthesis includes a literal valid quote-object example from retrieved evidence. A quote repair re-asks the same grounded question with that shape; it never fills in missing quotes automatically, normalizes a paraphrase into an exact quote, or bypasses validation. `coverage` reports elapsed milliseconds, accepted/rejected findings, model call attempts, the sum of output-token limits (explicitly not actual token usage or a price), and separate initial/final repair rejection counts. The maximum declared output-token limits are 6,200 across three attempts. No dollar cost estimate is fabricated.

The final deployed human-challenge regression returned `ok` in 19,426 ms server time: one accepted finding, two quote-format rejections, twenty-one retained sources, two model calls, no repair, and a 3,800-token output-limit sum (not actual billed usage). Both focused IDs survived clipping and every accepted quote matched fresh record-API evidence. The accepted draft corrected the earlier back-to-back claim using intervening room posts and used the recorded actor name. Its wording still overreached when excluding an internal loop; a final prompt clarification now explicitly forbids both proving and disproving hidden mechanisms from those observations and forbids presupposing an unobserved cause in an unknown. No further live model experiment was run after that clarification; semantic review remains necessary.

Sanitized machine-readable results are saved in [investigator-validation.json](investigator-validation.json), including the frozen backend hash. The file contains no raw traces, source IDs, credentials, or model payloads.
